# Deploy Note — Certification Roadmap (chain view + print/PDF)

**Date:** 2026-09-03 · **Scope:** `/compliance`'s Certification Milestone section rebuilt from three disconnected lists into one dependency-ordered roadmap, plus a landscape print/PDF hand-over. **Backend + frontend, no data migration required** (schema auto-migrates on boot).

## Why this deploy exists

The 2026-09-02 release seeded the Certification Milestone Plan (GRQ-PLAN-2026-01 v3.0) as 16 rows and correctly repointed GRC-KPI-002 at real delivery data — but rendered the plan as three disconnected boxes (Milestone Timeline / Compliant-From-by-Framework / Dependencies & Blockers). That severed exactly what the source document asserts: the milestone chain that "cannot be shortened," which milestone unlocks which framework, and which cross-department dependency gates which milestone. There was nothing presentable to the Head of GRQ (Ahmed) — Sarah's feedback after that release. This deploy fixes that: the same 16 rows, now drawn as one ordered chain with blockers attached to what they block, an Unlocks footer, framework readiness, and a print export built from the same live data.

The KPI itself (GRC-KPI-002's calculation, its `milestone_type = 'plan'` filter, the 16 seed rows' existing fields, RBAC roles) is **unchanged by this release** — this is a presentation layer on top of it.

## Known limitations / follow-ups

- **The relationship backfill re-fires as a harmless no-op on every boot** and logs `🔗 [NorthStar] Linked roadmap relationships on N milestone row(s)` (observed as "~9 rows linked" in earlier testing) each restart — some columns (e.g. `depends_on_key` on the chain head, `unlocks_codes`/`gates_keys` on rows that don't apply) are permanently `NULL` by design, so the `WHERE col IS NULL` guard keeps matching them. This is expected, not a leak or a growing table.
- **The print "Generated on" date is UTC** (`new Date().toISOString()`), so printing the roadmap between 00:00–03:00 KSA shows the previous calendar day. This follows an existing repo-wide convention already present in 7 other dashboards — not a new inconsistency introduced by this deploy.
- **The chain's node labels are an explicit i18n map**, not derived generically. An operator-added milestone whose key isn't in that map falls back to a slug derived from its key (e.g. `PLAN-2027-03-FOO` → "Foo") rather than a curated label — acceptable as a fallback, but it will look rougher than the seeded rows until the map is extended.
- **Carried forward and still open from the 2026-09-02 release:** the leadership feed's GRC-KPI-002 entry emits a raw **count** while its description prose says "percentage," and `componentFraction` folds that count as `count/100` in the North Star composite. Both are currently inert — the leadership push entry for this KPI is still committed commented out pending UUID verification (see the 2026-09-02 deploy note) — but become live once Q1 2027 weights apply. **This must be reconciled before 2027-01-01.**
