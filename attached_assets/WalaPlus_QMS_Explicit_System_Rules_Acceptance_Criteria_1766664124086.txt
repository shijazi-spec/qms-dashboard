WalaPlus QMS & GRC – Explicit System Rules, Descriptions & Acceptance Criteria

SECTION 1: EXPLICIT SYSTEM RULES (IF → THEN)

Governance Library
IF a policy/SOP is created or updated
THEN the system must:

- Require assignment of two owners:
  - Operational Owner (Quality)
  - Compliance Owner (GRC)
- Enforce versioning (no overwrite)
- Log change reason, editor, date, and impacted controls
- Block approval unless required compliance owner approves

IF a governance document is linked to a control
THEN it becomes mandatory evidence for audits and compliance checks

Risk & Findings Register
IF a finding is created from any source (Quality Audit, Vendor Review, Incident, Regulator)
THEN the system must:
- Auto-create or link to an enterprise risk
- Require risk category, impact, likelihood, owner
- Lock risk acceptance/closure to GRC roles only

IF risk status is “Accepted” or “Residual Risk Approved”
THEN only GRC Manager role can perform the action

Control Map
IF a control exists
THEN it must be mapped to:
- At least one BU process
- At least one governance document
- At least one testing method (audit, review, system check)

IF a control has no active evidence
THEN control status is automatically marked “Not Ready”

Action Tracker (CAPA)
IF a risk or finding is created
THEN at least one action must be created with:
- Owner (BU)
- Due date
- Required evidence
- Status

IF an action is overdue
THEN system escalates automatically and flags executive dashboard

Executive Dashboard
IF user role = Executive / CEO
THEN system only displays:
- BU Quality Maturity
- Risk Exposure
- Control Readiness
- Improvement & Automation Impact

AI Behavior
IF AI detects an issue, gap, or trend
THEN AI may:
- Recommend actions
- Highlight risk
- Suggest prioritization
BUT:
- AI cannot approve, close, or accept risk
- Human confirmation is always required

SECTION 2: SYSTEM DESCRIPTIONS (FOR REPLIT IMPLEMENTATION)

The QMS shall function as a single operating system that unifies:
- Quality execution
- GRC governance
- Risk & compliance management
- AI-powered insight and prioritization

The system must:
- Enforce ownership boundaries between Quality and GRC
- Prevent duplicate objects (risk, control, action)
- Maintain full audit logs for all create/update/delete actions
- Allow AI to analyze data without executing decisions

Roles:
- Quality Manager (Sara): audits, findings, improvement plans, training
- GRC Manager (Maram): risk logic, controls, compliance approval
- AI Specialist: model tuning, insights, dashboards (no approvals)
- BU Owners: action execution and evidence submission
- Executive: read-only strategic views

SECTION 3: ACCEPTANCE CRITERIA (FOR REPLIT)

Governance Library
- [ ] System enforces dual ownership
- [ ] Versioning cannot be bypassed
- [ ] Full audit log visible per document

Risk & GRC
- [ ] Risks cannot be accepted by Quality roles
- [ ] Risk register is single and enterprise-wide
- [ ] Risks link to findings, controls, and actions

Controls
- [ ] Each control shows mapped process, document, evidence
- [ ] Control readiness auto-calculated

Actions
- [ ] No finding closes without evidence
- [ ] Overdue actions auto-flagged

AI
- [ ] AI recommendations are visible and explainable
- [ ] AI actions require human confirmation

Security & Logs
- [ ] All actions logged (create/update/delete/view)
- [ ] Logs immutable and exportable

Executive View
- [ ] Dashboard limited to 4 strategic views
- [ ] No operational noise visible
