What Replit Got Wrong
Replit said: "There's no automatic real-time sync" and "we could add daily duplicate scans too."

Actually, you already have a 6-hourly auto-sync running via Inngest cron (duplicate-radar-auto-sync, cron 0 */6 * * *). This was added in v4.3 of the SOP. So the platform DOES automatically pull changes from Zoho 4 times a day.

However -- There's a Real Issue with Merges
When you merge records in Zoho (not just edit them), one record gets deleted. This is where the current sync has a gap:

Incremental sync (runs every 6h) uses Modified_Time > last_sync_time to fetch changed records from Zoho
Deleted records don't appear in Zoho's API response -- they're just gone
The platform has a markStaleRecords() function that's supposed to detect this, but it has a subtle bug: it only marks records as stale if they're NOT in the batch it just fetched. In incremental mode, that batch only contains modified records, so the deleted ones may stay as "ghosts" until a full sync is triggered
So yes -- after a merge session in Zoho, the merged-away records WILL linger in your Duplicate Radar until a full scan runs.

Best Practice Recommendation
Here's what I recommend, in order of priority:

1. After Every Merge Session in Zoho -- Do Both Sides
In Zoho:

Merge the duplicates as normal (keep primary, merge others into it)
Then in WalaPlus /duplicates:

Open each cluster you just merged
Click "Mark as Resolved" (or "Ignore" if you merged in Zoho without the platform's help)
This records the resolution in your platform for reporting/KPI tracking (SDR-KPI-09: Duplicate Rate ≤2%)
Click "Scan from Zoho" once at the end to force a full sync and clean up deleted ghosts
Why mark resolved in platform: Your KPI dashboards, owner accountability RAG, and management review reports all count "resolved clusters." If you only merge in Zoho without resolving in the platform, you lose the audit trail of who fixed what, when.

2. Two Improvements Worth Adding to Replit
A. "Last Synced" banner -- yes, accept Replit's offer. This is genuinely useful:

Shows "CRM data last synced 2 hours ago" on /duplicates page
Shows a warning badge if sync is older than 8 hours
Already have the backend (/api/duplicates/sync-state), just needs frontend display
B. "Sync Now" button -- a one-click manual incremental sync button (not a full rescan). Useful right after a merge session to instantly see the updated list without waiting for the 6h cron.

3. Skip These "Improvements"
Replit's suggestion to "add a daily duplicate scans too" -- ignore this. You already have 6-hourly auto-sync (4× better than daily). Adding a daily cron on top would be redundant.

4. Longer-term: Zoho Webhooks
The proper real-time solution is to register a Zoho CRM webhook that notifies the platform when any Lead/Deal/Contact/Account is created, updated, or deleted. This would eliminate the ghost-record problem entirely.

Effort: Medium (need to set up webhook endpoint with HMAC validation)
Value: High (true real-time sync, no ghost records, no waiting for cron)
Note: This is the only way to fully eliminate the merge-delete gap
