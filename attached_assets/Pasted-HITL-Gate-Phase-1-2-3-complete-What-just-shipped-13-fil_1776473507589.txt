How your controlled documents flow into the system
Boot seed: on first startup, seedControlledDocumentRegistry() inserts all 140+ WP documents into the existing policies table (status='draft', no file attached, ON CONFLICT DO NOTHING so it's re-run safe).
Upload path: Quality Manager goes to /policies → finds e.g. WP-SOP-011 → clicks Upload → attaches the approved .docx → POST /api/documents/upload stores the file + bumps version → policy_versions history is preserved automatically.
Everywhere else: every HITL approval card has clickable chips like WP-SOP-011 · v1.2 that open the exact controlled document the QM needs to read before approving.
No new document-management code was built — I reused your existing policy governance infrastructure.
