Pre-flight (2 minutes)
a) Confirm env vars are set on Replit:

OPENAI_API_KEY → needed for /intake GPT-4o extraction
MANUAL_INTAKE_DIR → recommend setting to a writable workspace path, e.g. ./data/manual-intake. Default is /data/documents/manual-intake which may not be writable on Replit.
b) Confirm the new role loaded:

Open the browser console on any logged-in page and run:

fetch('/api/admin/users').then(r => r.json()).then(console.log)
You should see head.ops.quality@walaplus.com in the list.

Flow 1 — Annual Audit Programme → HITL sign-off (≈ 5 min)
Session A: Quality Manager drafts and submits

Sign in as quality.manager@walaplus.com
Navigate to /audits
At the top of the page you'll see the Annual Audit Programme panel (indigo gradient, ISO 19011 §5.2 badge)
Click Draft → subtitle should change to show a programme code like PROG-2026-01, status chip turns gray ("Draft")
(Optional but recommended) — add at least one planned audit. If you don't, the next step will reject with Programme has no planned audits. Fastest way:
curl -X PUT http://localhost:5000/api/audit-programme/1 \
  -H "Content-Type: application/json" \
  -H "Cookie: <your-session-cookie>" \
  -d '{"planned_audits":[{"title":"ISMS Internal Audit","scope":"SAMA CSF","planned_q":"Q2"}]}'
Or extend the UI — the panel currently only supports Draft/Submit, not adding audits inline.
Click Submit for sign-off
Expected: alert with action code like AI-HIGH-000123, panel status flips to amber "Pending Sign-off", and the "View HITL queue" link now has a real ticket behind it.
Session B: Head of Operations & Quality approves

(Sign out → sign in as head.ops.quality@walaplus.com) — or open a private window
Navigate to /ai-approvals
Expected: a card titled Audit Programme Sign-off — PROG-2026-01 with risk=HIGH and compliance refs (WP-SOP-040, WP-CTL-007, ISO 19011:2018 §5.2)
Expand the payload preview → verify title, year, planned-audit count
Click Approve
Navigate back to /audits
Expected: Programme panel shows:
Status chip flips to green "Approved"
Approved By → head.ops.quality@walaplus.com
Approved At → current timestamp
Negative-path sanity checks (optional but good for auditability):

Try approving as the drafter → should 403 with "Segregation of duties: you cannot approve a programme you drafted"
Try submitting again from approved state → should 409 "Cannot submit from status 'approved'"
Flow 2 — Manual Audit Intake → GPT-4o extraction → promote (≈ 8 min)
Prep a sample report. The easiest file type for first test is a plain .md or .txt with findings in clear prose. Save this as finance-audit-sample.md:

# Finance Process Audit — March 2026
**Auditor:** Sarah Hijazi
**Date:** 2026-03-15
## Finding 1: Segregation of duties in vendor payments
The same user (finance.clerk@walaplus.com) creates vendor records AND approves
payments > 50,000 SAR. This violates WP-SOP-017 §4.2. Risk: major.
## Finding 2: Missing dual signatures on approvals
3 of 20 sampled payments lacked the second approver signature on the payment
voucher. Observation only — root cause appears to be absence of the backup
approver during March.
## Finding 3: No evidence of bank reconciliation for February
Bank reconciliation for Feb-2026 was not found in the evidence folder.
Classification: critical.
Steps:

Sign in as quality.manager@walaplus.com
Navigate to /audits → click Manual Intake (or go direct to /intake)
Click New Intake → drawer opens
Fill in:
Title: Finance Process Audit — March 2026
Source department: Finance
Audit date: 2026-03-15
Auditor: Sarah Hijazi
Report file: finance-audit-sample.md
Submit → intake appears in the list with status uploaded, code like INT-2026-001
Click Review next to the row
In the detail pane, click Run AI Extraction
If the file parsed natively, findings appear immediately
If the paste-fallback textarea appears, paste the same markdown content and click Extract again
Expected: 3 findings appear with severity chips (major / observation / critical), confidence scores, and a "source quote" block showing the exact paragraph GPT-4o read it from
For finding 1 (SoD): click Accept
For finding 2 (observation): edit the title to something clearer, click Save Edits → status flips to edited
For finding 3 (critical): click Accept
Click Promote Accepted to Findings (Finalize)
Expected: success message with count, intake status flips to finalized
Navigate to /audits → Findings section → you should see the 3 new rows with codes like NCR-* referencing the intake
Troubleshooting:

If extraction returns 500 with OPENAI_API_KEY missing → set it in Replit secrets and redeploy
If upload 500s with ENOENT or EACCES → set MANUAL_INTAKE_DIR=./data/manual-intake in Replit secrets
If the extractor returns 0 findings → paste the raw text via the fallback; native PDF parsing is a future enhancement
Flow 3 — Trigger HITL + dismiss-reason + auto-escalate (≈ 5 min)
Sign in as any Quality user
Navigate to /qms → Triggers tab
Find any trigger row (severity doesn't matter for the dismiss test; pick a critical one for the HITL test)
Click Dismiss on any trigger
Prompt appears asking for a reason
Type test (<10 chars) → Expected: 400 error "dismiss_reason is required (min 10 characters)"
Type Duplicate trigger — already captured under CAPA-2026-042 → Expected: success, trigger card shows "dismissed" state
Pick a critical severity trigger → click Propose via HITL
Prompt for optional notes → type something like Needs QM sign-off before we stop tracking
Expected: alert with an action code (e.g. AI-HIGH-000124), trigger flips to acknowledged
Navigate to /ai-approvals → the HITL ticket should be there with toolId trigger_decision
Auto-escalation (optional — normally runs at 03:00 daily):

To test without waiting, connect to the DB and backdate a trigger:

UPDATE audit_triggers
   SET created_at = NOW() - INTERVAL '8 days'
 WHERE severity = 'critical' AND status = 'pending'
 LIMIT 1;
Then trigger the cron manually:

curl -X POST http://localhost:5000/api/inngest \
  -H "Content-Type: application/json" \
  -d '{"name":"cron/trigger-auto-escalate"}'
Or in the Inngest dashboard, find trigger-auto-escalate and click "Invoke".

Expected outcome:

The backdated trigger now has status='actioned', auto_escalated_at=NOW(), escalation_finding_id=<new_id>
A new row exists in grc_audit_findings with finding_code='AUTO-ESC-<trigger_id>', severity major, status open
/audits → Findings list shows the new auto-escalated finding
Dismissed trigger re-evaluation: if you UPDATE audit_triggers SET next_reevaluate_at = NOW() - INTERVAL '1 hour' WHERE status='dismissed' LIMIT 1; then invoke the cron, the dismissed row flips back to pending with reevaluated_at=NOW()
