REPLIT FEATURE REQUIREMENTS – MULTI-SCORECARD EVALUATION ENGINE (AGENTIC AI)

GOAL
The system must support multiple Evaluation Scorecards (templates) across Commercial teams (SDR, Sales, CS, Marketplace, etc.).
Each scorecard is configurable and mapped to:
- CRM Module (Leads / Deals / Accounts / Contacts)
- Team (SDR Team, Sales Team, etc.)
- Linked Governance Document (knowledge source for AI)

The Agentic AI must always know:
1) Which governance document(s) to learn from
2) Which evaluation scorecard to use
3) Which records to evaluate based on module + team mapping


PAGE BEHAVIOR – EVALUATION SCORECARD

1) SCORECARD SELECTION (TOP SECTION)
The page must allow selecting one scorecard from many.

Fields:
- CRM Module (dropdown)
- Team (dropdown)
- Linked Governance Document (dropdown – active docs only)
- Scorecard Name (dropdown – multiple scorecards allowed per team/module)

Examples:
- SDR Team / Leads → “SDR Lead Hygiene Scorecard”
- Sales Team / Deals → “Sales Deal Governance Scorecard”
- Sales Team / Deals → “Sales Deal Velocity Scorecard”

System must support MULTIPLE scorecards per team/module.


2) SCORECARD ATTRIBUTES (EDITABLE)
Each scorecard contains multiple attributes (controls).

Each Attribute must have:
- Attribute Name
- Dimension: People / Process / Governance
- Short Description
- Weight
- Severity (Critical / Major / Minor – optional)
- Evaluation Logic (how AI checks it)
- Evidence Source (CRM fields, activities, attachments)
- Active toggle (enable/disable)

User must be able to:
- Add Attribute
- Edit Attribute
- Remove Attribute
- Reorder Attributes
- Change Attribute Weights


3) DIMENSION WEIGHTS
Dimension sliders must remain:
- People
- Process
- Governance

Rules:
- Total must equal 100%
- Attributes inherit weighting within their dimension


DATA MODEL (RECOMMENDED)

Entity: ScorecardTemplates
- id
- scorecard_name
- crm_module
- team
- linked_governance_doc_id
- version
- is_active
- created_by
- created_at

Entity: ScorecardAttributes
- id
- scorecard_template_id
- dimension
- attribute_name
- description
- weight
- severity
- evaluation_logic
- evidence_fields
- is_active
- order_index


AI MAPPING RULES (CORE)

When evaluating a record, the Agentic AI must:
1) Identify CRM module (Lead / Deal / Account / Contact)
2) Identify team context (SDR / Sales / etc.)
3) Load the ACTIVE scorecard mapped to module + team
4) Load linked governance document(s)
5) Evaluate the record using scorecard attributes
6) Output:
   - Score per dimension
   - Attribute pass/fail with reasoning
   - Evidence used
   - Recommended corrective actions


MULTIPLE SCORECARDS LOGIC
If more than one scorecard exists for the same module/team:
- Use the one marked as “Active”
- Or allow manual selection during evaluation


REQUIRED UI ADDITIONS
- Create New Scorecard button
- Scorecard Management page (list, edit, delete)
- Clone Scorecard feature
- Versioning (v1.0, v1.1, v1.2…)
- Set Active Scorecard toggle per team/module


BUSINESS REASON
Each department has different governance logic:
- SDR → Lead hygiene & readiness
- Sales → Deal lifecycle & revenue governance
- Marketplace / CS → separate rules

Scorecards must be isolated, configurable, and explicitly linked to the governance document the AI learns from.
