“SDR Call Quality Evaluator Agent” (Arabic/Saudi)
Objective

Build an Agentic AI that can evaluate SDR calls end-to-end:

Accept an uploaded call recording (audio file)

Transcribe it (Arabic – Saudi dialect focus) with timestamps and speaker separation

Understand what happened in the call professionally (sales + SDR context)

Evaluate the call using the SDR Evaluation Form attributes (provided dynamically by the system/admin)

Output scores + pass/fail/NA decisions + evidence-based comments per attribute

Create an overall quality summary and improvement actions

This agent must behave like a Quality Expert / QA Specialist for SDR calls.

Inputs (What the agent receives)

The agent will receive:

A) Audio

audio_file (wav/mp3/m4a)

Metadata if available: agent_name, call_date, call_direction, call_duration, call_source

B) Evaluation Form (Dynamic)

The form is configurable by admin. Each attribute includes:

attribute_name

description

dimension (People / Process / Governance)

weight

target

severity (Minor / Major / Critical)

evaluation_logic (how to decide pass/fail/NA)

scoring_type (score range or pass/fail)

evidence_fields (optional)

Required Output (Strict Structure)

After processing, the agent must output a structured JSON response:

1) Transcript Output

Language: Arabic (Saudi) + optional English summary

Must include:

timestamped_transcript

speaker_labels (Agent / Customer)

confidence_score

key_moments (greeting, discovery, objections, close, next step)

2) Evaluation Output

For each attribute, return:

attribute_name

score (or pass/fail if configured)

status: PASS / FAIL / NA

severity

evidence_quotes (short excerpts, max 1–2 lines)

evidence_timestamps (start–end)

comment (professional, actionable)

improvement_tip (one clear tip)

3) Overall Summary

overall_score

dimension_scores (People/Process/Governance)

top_strengths (max 3)

top_gaps (max 3)

coaching_actions (max 5)

critical_risks (if any)

4) Recommendation / Coaching

Suggested coaching message to the agent (Arabic + optionally English)

Suggested micro-training topics based on gaps

Evaluation Rules (How the agent must think)

The agent must:

Follow the form’s logic exactly (do not invent new rules)

Use evidence from transcript only

If evidence is missing or call didn’t reach that section, mark NA

Do not penalize the agent for things the customer never allowed to happen (e.g., call cut off early)

Be consistent: same behavior should receive similar scoring

Prefer Saudi Arabic understanding (common phrases, tone, politeness, indirect expressions)

Detect professional behaviors:

greeting, consent, purpose, rapport

discovery questions and active listening

product explanation accuracy

objection handling quality

closing and next steps clarity

compliance statements if required

Arabic (Saudi) Requirements

Transcription must support:

Saudi dialect variations

Arabic numerals and mixed Arabic/English terms (e.g., “CRM”, “Zoho”, “bundle”)

Quality comments should be written in professional Arabic suitable for coaching.

If the admin wants English comments, add an optional toggle.

Safety / Privacy Requirements

Do not expose unnecessary PII in outputs

Mask phone numbers/emails if mentioned

Transcript should be stored securely with access control

Log who evaluated, when, and what version of the scorecard was used

System Workflow Requirements

Upload audio → create call record

Transcribe (with timestamps + speakers)

Evaluate using active scorecard attributes

Save evaluation results + audit trail

Show results in “SDR Evaluation” UI

Trigger notifications if:

Critical failures

Low score

Repeated gaps for same agent

Scoring Guidance

If form uses numeric scoring:

Score must align with:

evidence quality

completeness

professionalism

If form uses pass/fail:

PASS only if requirement is clearly met

FAIL if clearly not met

NA if not applicable or no evidence

Developer Notes (Implementation)

Use an Arabic-capable speech-to-text pipeline with diarization (speaker separation).

Store transcript, timestamps, and confidence score.

Evaluation agent uses transcript + attribute rules only.

Keep outputs deterministic where possible (same transcript → similar scoring).
