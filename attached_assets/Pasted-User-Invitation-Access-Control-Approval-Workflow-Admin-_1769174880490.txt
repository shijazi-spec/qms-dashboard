User Invitation + Access Control + Approval Workflow (Admin Panel)
Goal

We are starting platform testing and need to invite internal team members to access the QMS platform.
We must implement a secure Admin User Management feature that supports:

Inviting users by email

Role-based access control (RBAC) + screen-level permissions

“Request access” approval flow (approve/deny)

Ability to customize what each user can see/do (view/edit/take actions/export)

Full audit trail for access decisions (PDPL accountability)

1) Admin Page: User Management (New Screen)

Create an Admin page accessible only to Admin/Owner:
Admin → Users & Access

This page must include tabs:

Invite Users

Pending Requests

Active Users

Roles & Permissions

Audit Log (Access Changes)

2) Invite Users (Email Invitation Flow)
Admin action:

Admin enters:

Email (required)

Full name (optional)

Team (dropdown): SDR / Sales / Quality / GRC / Viewer / Other

Role (dropdown): choose pre-defined role OR “Custom”

Optional: expiry date for invitation link

Optional: require MFA toggle (recommended)

System action:

Send email invitation with secure token link

Link leads to “Create account / Sign in” page

Invitation expires after X days (configurable)

Invitation token can only be used once

3) Access Request Approval (Mandatory Gate)

After user clicks invitation link and submits signup:

Status becomes:

Pending Approval

Admin must review:

User details (email, name, team)

Requested role/permissions

Reason for access (short text field on signup)

Requested modules/screens (if custom)

Admin actions:

Approve

Deny

Request Changes (send back with notes)

On Approve:

Status = Active

User gains access based on assigned role/permissions

System sends “Access Approved” email

On Deny:

Status = Denied

User cannot login

System sends “Access Denied” email with generic message

4) Roles & Permissions Model (RBAC + Screen Level)

Implement a permissions system that supports:

A) Role-based access (prebuilt roles)

Suggested default roles:

Owner/Admin (full access)

Quality Manager

Quality Specialist

GRC Manager

Team Lead (Sales/SDR)

Department Viewer

Auditor (read-only + export disabled)

B) Permission types (granular)

Each screen/module must support:

View

Create

Edit

Delete

Approve/Reject

Assign

Run AI Audit

Export/Download

Upload documents

Manage settings

Manage users

C) Screen/module coverage

Permissions must be controllable per section, for example:

Governance Documents

Evaluation Scorecards

Run AI Audit

Audit History

Issues / Nonconformances

CAPA

Training

Framework

Analytics

Settings

Admin (users & roles)

D) Custom role

If Admin selects “Custom”, allow toggling permissions per screen and action.

5) Data Access Scoping (Team/Module Restrictions)

We need to control “what data a user can see”, not only screens.

Example:

SDR user should see only Leads module audits

Sales user should see only Deals module audits

Quality can see all modules

GRC can see governance docs + PDPL + audit trails, but not CRM confidential fields

Implement:

Team scope (SDR, Sales, Quality, GRC)

Module scope (Leads, Deals, Accounts, Contacts)

Record scope (All records vs only assigned owners)

6) Audit Trail for Access Changes (PDPL Accountability)

All access events must be logged (immutable):

Invitation created (who invited, email, role)

Invitation accepted

Approval/deny decision (who approved/denied + timestamp + notes)

Role/permission changes

Account disable/enable

Login attempts (optional)

Show these logs in:
Admin → Audit Log

7) UI Requirements (Simple but Clear)
Admin User List must show:

Name

Email

Role

Team

Status (Invited / Pending Approval / Active / Denied / Disabled)

Last login

Actions (Approve/Deny/Edit/Disable/Reset)

Pending Requests page:

Must show all pending users

Bulk approval optional

Approve must allow editing permissions before final approval

8) Security Requirements

Invitation links are token-based and expire

Prevent user from accessing any page until approved

Default role for new users = no access until approval

Export/download restricted by role

Admin actions require confirmation

Password policy + optional MFA

9) Acceptance Criteria (Must Pass)

Admin can invite by email

User can accept invitation and submit request

Admin can approve/deny

Approved user can access only allowed screens/actions

Denied user cannot login

Admin can edit permissions anytime

All actions logged in audit trail
