WalaPlus Quality System – Event Logs Feature
Business Case & Technical Specification
Version 1.0

------------------------------------------------------------
1. PURPOSE
------------------------------------------------------------
This document defines the requirements to build a complete “Event Logs”
feature inside the WalaPlus Quality Management & Agentic AI System.

The Event Logs module must:
- Track every action performed inside the system (create, edit, delete, assign,
  AI actions, calculations, training updates, etc.)
- Give visibility through a dedicated UI page
- Enable Admins & Quality Managers to audit system usage
- Guarantee that no change happens without a corresponding audit log

------------------------------------------------------------
2. SCOPE
------------------------------------------------------------
The feature will include:
1. Event Logs Button (visible only to Admin & Quality Manager)
2. Event Logs Page (table view with filters)
3. Backend Logging Function (centralized)
4. Database Table for Logs
5. API Endpoints for Logs
6. Security & Permissions
7. AI Visibility on Logged Events (optional)

------------------------------------------------------------
3. UI REQUIREMENTS
------------------------------------------------------------

A. Event Logs Button
- Add a navigation button labeled “Event Logs”
- Visible only to roles: Admin, Quality Manager
- On click: navigate to /logs or open logs panel

B. Event Logs Page
- Title: “System Event Logs”
- Table Columns:
  * Date & Time
  * User (name + email)
  * Role
  * Action Type
  * Entity Type (Project, Training, ROI, User, etc.)
  * Entity ID / Name
  * Description
  * AI Involved (Yes/No)

- Filters (top bar):
  * Date Range
  * User
  * Action Type
  * Entity Type
  * AI Involved (Yes/No)

- Pagination: Default 25 logs per page
- Each row can expand to show:
  * Old Value
  * New Value
  * IP Address
  * User Agent
  * Correlation ID

------------------------------------------------------------
4. EVENTS TO BE LOGGED
------------------------------------------------------------

A. Projects / Governance Documents
- Created
- Updated
- Deleted
- Status change
- Stakeholder added/removed
- Due date changed

B. Training Module
- Training created
- Training updated
- Training assigned
- Training completion updated

C. ROI / NPV Engine
- ROI case created
- ROI recalculated
- Inputs changed
- Initiative status changed (Draft, Submitted, Approved, Rejected)

D. Users & Roles
- User created
- Role modified
- User deactivated/reactivated

E. AI Actions
- AI-generated project scope
- AI suggestions accepted/rejected
- AI validation run

F. Deletions (Critical)
- Any entity deletion must be logged

G. Authentication (Optional)
- User login
- User logout

------------------------------------------------------------
5. LOG ENTRY MODEL
------------------------------------------------------------
Table: event_logs

Fields Required:
- id (primary key)
- timestamp (datetime)
- user_id (nullable for system actions)
- user_name
- user_email
- user_role
- action_type (CREATE, UPDATE, DELETE, STATUS_CHANGE, ASSIGN, AI_ACTION)
- entity_type (PROJECT, TRAINING, ROI, USER, ROLE, etc.)
- entity_id
- entity_name
- description (text)
- old_value (JSON or text)
- new_value (JSON or text)
- ai_involved (boolean)
- ip_address (text, optional)
- user_agent (text, optional)
- correlation_id (optional)

------------------------------------------------------------
6. CENTRAL LOGGING FUNCTION
------------------------------------------------------------
Create a universal function:

logEvent({
  userId,
  userName,
  userEmail,
  userRole,
  actionType,
  entityType,
  entityId,
  entityName,
  description,
  oldValue,
  newValue,
  aiInvolved,
  ipAddress,
  userAgent,
  correlationId
})

This function must:
- Write to event_logs table
- Never break main flow on error
- Automatically capture timestamp

------------------------------------------------------------
7. API ENDPOINTS
------------------------------------------------------------

GET /api/logs
- Params: page, pageSize, user, actionType, entityType, aiInvolved, fromDate, toDate
- Returns paginated filtered logs
- Restricted to Admin & Quality Manager

GET /api/logs/:id (optional)
- Returns full log detail

------------------------------------------------------------
8. SECURITY & PERMISSIONS
------------------------------------------------------------
- Only Admin & Quality Manager can access Event Logs
- No editing or deleting logs
- Logs are append-only
- Frontend hides the button from other roles

------------------------------------------------------------
9. UX NOTES
------------------------------------------------------------
- Default sort: newest first
- Clear "No Logs Found" message
- Search box for user or description
- Detailed entries when expanded

------------------------------------------------------------
10. GOAL
------------------------------------------------------------
Once implemented:
- Every action in the QMS is recorded
- Admins and Quality Managers have complete audit visibility
- Full traceability for governance, training, ROI, AI actions, and operations
- Supports compliance, COPC governance, and internal audits
