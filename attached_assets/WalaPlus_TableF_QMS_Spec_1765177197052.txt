WalaPlus QMS - Table F Governance Engine (COPC 50/75) - Full Business Specification

1. PROJECT OVERVIEW
Purpose:
Build a COPC-compliant Table F module inside the existing WalaPlus Quality Management System (QMS) and Agentic AI project. This module will track KPIs, apply the COPC 50%/75% rule, and provide governance visibility across all commercial and support functions.

Scope Departments (initial phase):
- Sales
- SDR / Presales
- Customer Support / Contact Center
- Marketplace
- WalaOne / Customer Success
- Operations & Quality
- Marketing
- Finance
- HR
- IT

Important:
- This MUST be built INSIDE the existing QMS / Agentic AI project (not a separate project).
- Initial phase uses manual KPI achievement entry.
- Later phases will integrate with Zoho, Five9, Calendar, Finance systems, HRIS, Marketing tools, IT monitoring, etc.

2. BUSINESS OBJECTIVES
- Centralize KPI tracking for all departments.
- Enforce COPC 50/75 rule for governance and certification readiness.
- Enable Agentic AI to monitor progress and recommend corrective actions.
- Provide clear executive visibility via Table F dashboards.
- Allow departments to define KPIs, targets, and manually input achievement until integrations are ready.

3. COPC BACKGROUND (TABLE F & 50/75 RULE)
COPC Requirement:
- At least 50% of required KPIs must be fully achieved.
- At least 75% of required KPIs must either be achieved OR show sustained improvement over the measurement timeline.
- Evidence must be available via a performance summary table (Table F) with monthly data, trends, and corrective actions.

WalaPlus Interpretation:
- For a 12-month cycle, at ~75% of the timeline (month 9), at least 50% of KPIs are achieved.
- Remaining KPIs must have non-zero progress and documented action plans.
- This logic must be evaluated per department and at company level.

4. HIGH-LEVEL FEATURES
4.1 KPI Management
- Create, edit, archive KPIs per department.
- Define KPI type (Customer, Quality, Service, Efficiency, Financial, People, Strategic, etc.).
- Set annual target, unit (%, count, SAR, index, etc.), weight, and owner.
- Capability to attach definition, calculation formula, and data source description.

4.2 KPI Performance Capture (Manual First, Integration Later)
- For each KPI and month:
  - Manually input achieved value (ACH).
  - System auto-calculates variance vs target.
  - System marks status (Met / Not Met / Improving / Deteriorating).
- Later, achievement values will be auto-populated from integrated systems (Zoho, Finance, HRIS, Marketing tools, IT monitoring, etc.).

4.3 Table F Engine
- Summarize all KPIs by department and overall.
- Evaluate COPC 50/75 rule:
  - 50% of KPIs fully achieved.
  - 75% of KPIs achieved or improving.
- Show status: COMPLIANT / AT RISK / NON-COMPLIANT per department and for WalaPlus overall.

4.4 Agentic AI Layer
- Analyze trends in KPIs.
- Identify which KPIs are blocking 50/75 compliance.
- Propose RCA categories (People, Process, Policy, Tools, Data, Client Dependency).
- Recommend actions and ownership.
- Highlight dependencies on integrations (e.g., Zoho for Sales FCR, Finance for EBITDA, HR for Attrition).

4.5 Access Control (Role-Based Access Matrix)
User roles:
- QMS Admin
- Department Owner / Manager
- Editor
- Viewer
- AI Agent (system role)

Access Matrix (high-level):
1) QMS Admin
   - Full system-wide access.
   - Create/modify/delete KPIs for any department.
   - Configure weights, targets, scoring rules, and 50/75 thresholds.
   - View and export all dashboards and reports.
   - Manage user roles and access rights.

2) Department Owner / Manager (e.g., Head of Sales, Head of Marketing, Head of IT)
   - Manage KPIs only for their department.
   - Create/edit/retire KPIs within their department.
   - Approve or edit monthly achievements (ACH) for their department.
   - View all Table F views for their department.
   - View company-wide summary (read-only).
   - Cannot modify other departments’ KPIs.

3) Editor (Analyst / Specialist)
   - Assigned per department.
   - Can input monthly ACH values for assigned department’s KPIs.
   - Can add comments, attach evidence, and draft RCA notes.
   - Cannot create or delete KPIs.
   - Cannot change targets, weights, or formulas.

4) Viewer (Executive / Stakeholder)
   - Read-only access.
   - Can view dashboards, KPI matrices, trends, and AI insights.
   - Cannot change data, targets, or configurations.

5) AI Agent (System)
   - Can read all KPI and Table F data.
   - Can write AI-generated insights, risk flags, RCA suggestions, and recommendations.
   - Cannot modify targets; any AI recommendations are suggestions only.

Access Matrix by Action (simplified):
- Create KPI: Admin, Department Owner
- Edit KPI (definition, target, weight): Admin, Department Owner
- Delete/Archive KPI: Admin, Department Owner
- Enter/Update KPI Achievement (ACH): Admin, Department Owner, Editor
- View Table F Dashboard: All roles
- Configure COPC rules (50/75 thresholds): Admin only
- Manage Users & Roles: Admin only

8. BACKEND LOGIC & 50/75 IMPLEMENTATION

8.1 Monthly Recalculation
- At minimum, recalculate Table F whenever:
  - ACH is updated.
  - Targets change.
  - New KPI is added.
- Also support scheduled recalculation (e.g., daily/nightly job).

8.2 COPC 50/75 Logic (per department)
- total_kpis = count of enabled KPIs.
- kpi_met = count where KPI is “Met” (YTD or within defined period).
- kpi_improving = count where KPI is not yet met but:
  - past 3 months show positive trend, OR
  - variance is reducing consistently.

- percent_met = kpi_met / total_kpis * 100
- percent_met_or_improving = (kpi_met + kpi_improving) / total_kpis * 100

Rules:
- If percent_met >= 50 AND percent_met_or_improving >= 75 → COMPLIANT.
- If percent_met < 50 but percent_met_or_improving >= 75 → AT_RISK.
- If percent_met_or_improving < 75 → NON_COMPLIANT.

8.3 AI Layer Behavior
- Input: KPI definitions, monthly data, department summaries.
- Output:
  - Risk level (Low/Medium/High) per department.
  - Top problem KPIs.
  - Suggested RCA categories.
  - Suggested actions (e.g., “Review sales training”, “Check Zoho data pipeline”, “Align Finance closing cycle”).

10. ACCEPTANCE CRITERIA

The Table F module is considered successfully implemented when:

- All roles (Admin, Owner, Editor, Viewer) behave exactly as specified.
- Departments (Sales, SDR, CS, Marketplace, WalaOne, Ops & Quality, Marketing, Finance, HR, IT) are all supported.
- KPIs can be created, maintained, and manually updated for ACH.
- Table F dashboard shows correct summaries and COPC 50/75 status.
- AI insights are generated and visible with at least:
  - Key risks.
  - Top problematic KPIs.
  - Suggested actions.
- System supports mock data and is ready to be integrated with live systems in later phases.

End of Specification.
