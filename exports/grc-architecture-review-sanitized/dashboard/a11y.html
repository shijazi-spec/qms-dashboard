Accessibility Statement

ExampleOrg Quality Management System

Partially Conformant — WCAG 2.1 AA

Our Commitment

ExampleOrg is committed to making its Quality Management System dashboard accessible to all users, including those with disabilities. We aim to conform with the Web Content Accessibility Guidelines (WCAG) 2.1 at Level AA.

Conformance Status

ExampleOrg QMS is partially conformant with WCAG 2.1 Level AA. Partial conformance means that some parts of the content do not fully conform to the accessibility standard. We are actively working to close remaining gaps.

What We Have Done

  • Added a skip to main content link that appears on keyboard focus, allowing keyboard users to bypass repeated navigation.
  • Implemented focus trap management in all modal dialogs, so keyboard focus stays within the dialog until it is closed.
  • All modal dialogs include role="dialog", aria-modal="true", and aria-labelledby pointing to the dialog heading.
  • All icon-only buttons carry descriptive aria-label attributes (e.g., Notifications, Refresh dashboard, Close dialog).
  • Interactive elements that were previously non-semantic <div> or <span> elements with click handlers have been converted to native <button> elements.
  • A consistent focus-visible ring (3 px solid indigo) is applied to all interactive elements for keyboard navigation.
  • The GRQ Assistant chat panel includes an aria-live region so assistive technologies announce new messages.
  • Navigation landmarks (<nav>, <main>, <aside>) are used throughout the dashboard.
  • Decorative SVG icons are hidden from assistive technology using aria-hidden="true".
  • All KPI and analytics charts include role="img" with an aria-label describing the chart, and a visually-hidden data summary table so screen reader users can access the underlying data.
  • Navigation tooltips now use a proper ARIA tooltip pattern — each tooltip carries role="tooltip" and is linked to its trigger via aria-describedby. Tooltips appear on both pointer hover and keyboard focus, replacing the previous title-attribute-only approach.
  • All data-heavy tables (audit findings, risk register, nonconformances/CAPA, compliance obligations and gap analysis) now include scope="col" on every column header, and select-all checkbox headers carry descriptive aria-label attributes.

Known Limitations

All previously identified limitations have been resolved. We continue to monitor the platform for any new accessibility gaps and will update this statement accordingly.

Technical Specification

ExampleOrg QMS is built with standard HTML5, Tailwind CSS, and vanilla JavaScript. It is compatible with the following assistive technologies:

  • NVDA + Chrome (Windows)
  • JAWS + Chrome or Edge (Windows)
  • VoiceOver + Safari (macOS / iOS)
  • TalkBack + Chrome (Android)

Feedback and Contact

We welcome feedback on the accessibility of ExampleOrg QMS. If you encounter accessibility barriers or need information in an alternative format, please contact us:

  • Email: user@example.invalid
  • In-app: Use the GRQ Assistant widget (bottom-right corner) and mention an accessibility concern.

We aim to respond to accessibility feedback within 5 business days.

Enforcement Procedure

If you are not satisfied with our response, you may contact the W3C Web Accessibility Initiative for further guidance on web accessibility standards and dispute resolution.

Preparation of This Statement

This statement was prepared on 24 April 2026. It is reviewed and updated whenever significant accessibility improvements are made to the platform.
