# WalaPlus Enterprise GRC & Quality Management Platform

## Overview
WalaPlus is an AI-powered enterprise Quality Management System integrating governance, risk, and compliance (GRC) with quality management. It features HTML dashboards, autoscale deployment, AI-powered quality audits, robust duplicate detection, page-view telemetry, and resumable streaming exports. The platform's core purpose is to provide a unified solution for modern enterprise quality and compliance, enhancing operational efficiency and regulatory adherence.

## System Architecture
The platform is built around a robust GRC and quality management framework, leveraging AI for key functionalities such as quality audits.
UI/UX decisions include:
- HTML dashboards for comprehensive data visualization.
- Integration of status indicators and alert banners (e.g., storage health, rate limit spikes) with interactive triage actions.
- Consistent application of CSP-safe practices for UI elements and event delegation.

Technical implementations and feature specifications include:
- **AI-Powered GRC**: Core AI capabilities for audits and compliance checks.
- **Telemetry and Monitoring**: Extensive logging (`logger.info/error/warn/debug`), `ai_call_metrics` retention with configurable windows and admin UI, prompt version purging, and page-view telemetry.
- **Alerting System**: Comprehensive alert management for storage health, tool health breaches, and rate limit spikes. Alerts are severity-tiered, with notification status tracking, dead-letter logging for failed deliveries, and configurable email/Slack recipients managed via an admin UI.
- **Security & Data Privacy**:
    - **Credential Redaction**: Proactive redaction of sensitive information (passwords, tokens) in logs, database entries, and user-facing error responses. This includes regex-based matching, key-name deny-lists, and heuristic detection for plain-text credentials in free-form fields (e.g., high entropy, character class analysis).
    - **Approval Gates**: Static analysis and runtime enforcement for AI tool usage, ensuring every tool has a defined governance policy with compliance references and a build preview function. Tools requiring approval are explicitly gated.
- **Database Management**: Utilizes `ai_call_metrics`, `ai_pending_actions`, `event_logs`, `ai_alerts`, `alert_email_recipients`, `ai_metrics_retention_config`, `ai_metrics_retention_audit`, and `prompt_version_purge_runs` tables for data storage and auditing.
- **Asynchronous Processing**: Leverages Inngest for cron jobs and background tasks, such as daily metric pruning, cost summaries, tool health checks, and rate limit spike monitoring.
- **API Endpoints**: RESTful APIs for accessing system configurations, audit logs, and operational data (e.g., `/api/ai-ops/storage-health-alerts`, `/api/ai-ops/metrics-retention`, `/api/ai-ops/prompt-versions/last-purge`).
- **Error Handling**: Standardized error wrapping and redaction of sensitive data in error messages before exposure.
- **Deployment**: Supports autoscale deployment.

### April 25, 2026 — Extended RTL guard to space-x-, rounded-l-/r-, and non-`<th>` text-left/right (Task #628)
Built on Task #315's three-rule baseline (`<th>` text-align, `border-l-4`/`border-r-4`, `<button>` ml-/mr-). The "RTL Layout Convention" section of `replit.md` listed several more physical-direction Tailwind classes that also break the Arabic experience but were not enforced; a routine edit to a new dashboard page could reintroduce one. Added three new rules to `scripts/check-rtl-classes.cjs`: (1) **spaceX** — any element with `space-x-<n>` (numeric / keyword like `space-x-px` / arbitrary `space-x-[5px]` / `space-x-reverse`); fix is `gap-<n>` on the flex/grid container since `space-x-*` compiles to physical `margin-left` between children and does not flip in RTL. (2) **roundedLR** — any element with `rounded-l-*` / `rounded-r-*` for every Tailwind value (`none`, `sm`, `md`, `lg`, `xl`, `2xl`, `3xl`, `full`, numeric, arbitrary `[…]`) AND the bare `rounded-l` / `rounded-r` shorthand; fix is `rounded-s-*` / `rounded-e-*`. The regex carefully excludes `rounded-lg` (radius-large, not directional) by anchoring the `l`/`r` to a token boundary or `-`. (3) **textLRNonTh** — any non-`<th>` element (`<td>`, `<div>`, `<p>`, `<li>`, `<span>`, …) with `text-left` / `text-right`; fix is `text-start` / `text-end`. The two text-align rules are tag-disjoint (thTextAlign owns `<th>`, textLRNonTh owns everything else) so a `<th>` violation never double-fires. Per-rule allowlists (`spaceX`: 18 currently-violating files; `roundedLR`: empty so the very first new violator fails immediately; `textLRNonTh`: 6 files) were inventoried by tokenising every `dashboard/*.html` and bucketing matches by the same per-tag regex the script uses, so the guard lands green and tightens over time. New negative-test coverage in `tests/noPhysicalDirectionClasses.test.ts` (16 assertions, was 10): one positive synthesis per new rule plus tag-disjointness for `text-left` on `<th>` vs `<div>`, plus three sentinels — `rounded-lg` does NOT misfire as roundedLR, `<script>` body strings are still skipped, and the result of a `text-right` match on a `<td>` is distinct from a `<th>`.
