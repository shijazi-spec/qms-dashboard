# WalaPlus Enterprise GRC & Quality Management Platform

## Overview
WalaPlus is an AI-powered enterprise Quality Management System that integrates governance, risk, and compliance (GRC) with quality management. It provides HTML dashboards, supports autoscale deployment, and offers comprehensive solutions for quality, risk, and compliance. Key capabilities include AI-powered quality audits, robust duplicate detection, page-view telemetry, and resumable streaming exports. The platform aims to be a holistic solution for modern enterprise quality and compliance needs, enhancing operational efficiency and regulatory adherence through a unified GRC and quality management approach.

### April 25, 2026 — Configurable retention for `ai_call_metrics` (Task #236)
The `ai_call_metrics` telemetry table was being pruned by the daily `ai-cost-summary` Inngest cron with a hardcoded 90-day window — fine for ops experimentation, but unworkable for high-volume agent workloads where operators need either a tighter window (e.g. 30 days) to keep the table fast or a wider window (e.g. 180 days) for trend analysis. ### April 25, 2026 — Block credentials from leaking into safe-error responses (Task #454)
We already redact credential-shaped substrings before WRITING anything to the database (event_logs, change_history, ai_pending_actions). However, when a route catch block returned `c.json({ error: "Failed to ...", details: error.message }, 500)` and the upstream SDK echoed the credential back in its exception text (e.g. "Invalid token sk-live-..."), the secret could still reach the user-facing HTTP response and a client-side toast — even though the same content was scrubbed at write time. Closed that asymmetry by adding a global response post-processor `redactSecretsInResponse(c)` in `src/mastra/middleware/index.ts` that runs after `await next()` and walks the body of any 4xx/5xx JSON response, applying `deepRedactSecretLikeStrings` to every string leaf so credentials are replaced with `REDACTED_SENTINEL`. Successful 2xx bodies and non-JSON responses are skipped (so we do not pay the cost of walking multi-MB list responses or corrupt HTML/file streams). The catch block itself was also hardened: errors that escape route handlers are rewrapped (preserving `name` and `stack`) with a redacted message before being rethrown to the default Hono error renderer, and `MastraError` / `ZodError` paths that wrap into `NonRetriableError` now redact too. New test `tests/safeErrorResponseRedaction.test.ts` (14 assertions, picked up by `npm test` auto-discovery) exercises sk-live-... in details, ghp_... in 4xx body, deeply nested Bearer tokens, the 2xx no-op, the non-JSON no-op, the byte-identical no-op, and the undefined-response tolerance.

### April 24, 2026 — True streaming exports to disk
Reworked `dashboard/js/streaming-download.js` so large exports flow directly to the user's filesystem instead of accumulating in a `Blob` in memory. When the browser supports the File System Access API (`window.showSaveFilePicker` + `WritableStream` + `TransformStream`) — i.e. modern Chromium — and the response either has no `Content-Length` or one ≥ 10 MB, the helper now opens a save-as picker and pipes `response.body` straight to `handle.createWritable()` via a progress-tracking `TransformStream`. ### April 24, 2026 — CSP guard: dashboard inline-handler lint check
